# 1. 시간대별 가이드

> ⏰ **제출 마감 11.22 · 07:30**
> 07:20부터 프로젝트를 제출해 주세요. 발표 준비 중에도 07:30 제출 마감을 지켜 주세요.


## 01. 16:40—19:00 — 아이디어와 초기 세팅
- 프로젝트를 초기 설정해 주세요.
  - 패키지 구조, 네이밍 규칙, GitHub 협업 규칙을 정해 주세요.
  - 한 명이 프로젝트를 생성하고 초기 설정을 마친 뒤 GitHub에 공유해 주세요.
- 주요 기능의 구현 우선순위를 정해 주세요.
- 레이아웃을 구성해 주세요.
  - 주제와 전체적인 틀이 정해지면 역할을 나눠 주세요.
  - 기획자·디자이너와 협업해 간단한 레이아웃부터 빠르게 준비해 주세요.
  - 오래 걸릴 것으로 예상되는 기능은 미리 공유하고 범위를 조정해 주세요.


## 02. 19:00—05:00 — 프로젝트 개발
- 나눠 맡은 기능의 개발을 시작해 주세요.
  - 수정 사항이나 일정 지연이 예상되면 팀원에게 바로 공유하고 이슈를 기록해 주세요.
- 레이아웃에 디자인을 적용해 주세요.
  - 자주 사용하는 drawable 파일은 함께 사용할 수 있도록 정리해 주세요.
  - 색상과 폰트 등 디자인을 설정하고, 준비된 화면부터 구현해 주세요.
- 기능을 구현하고 API를 연결해 주세요.
  - 서버 API가 준비되면 하나를 먼저 연결해 정상 동작을 확인해 주세요.
  - 주요 기능은 화면을 구현한 뒤 바로 API를 연동해 주세요.
- 협업 문서를 주기적으로 동기화해 주세요.


## 03. 05:00—07:40 — 최종 점검과 발표 준비
- 주요 기능 구현을 마무리해 주세요.
  - 발표 3시간 전까지는 주요 기능을 최대한 완성하고 보완 작업을 시작하는 것을 권장해요.
  - 추가 기능은 우선순위에 따라 구현해 주세요.
- 기능과 레이아웃을 보완해 주세요.
  - 구현한 기능을 테스트하고 기획자와 논의해 부족한 부분을 보완해 주세요.

# 2. 유의사항

1. 화면 수를 최소화해 주세요.
2. 세부적인 꾸밈보다 MVP 완성에 집중해 주세요.
3. 사용자의 흐름이 끊기지 않도록 UI/UX를 정리해 주세요.
4. 복잡한 구조는 피하고, 아키텍처를 빠르게 정해 팀에서 통일해 주세요.
5. Socket, SSE 같은 실시간 통신은 가능한 한 제외해 주세요.
6. ProGuard 설정이 익숙하지 않다면 이번에는 사용하지 않는 것을 권장해요. 릴리즈 빌드 실패를 줄이는 데 도움이 돼요.
7. 협업 문서는 주기적으로 동기화해 주세요.

# 3. 심사기준

**기본 총점 100점** (가산점 최대 10점)



## 01. 서버 통신 (15점)
#### 채점 방법
- 임시 데이터 대신 실제 서버와 통신하는지 확인해요.
- 네트워크 오류와 잘못된 데이터를 처리하며 정상적으로 통신하는지 살펴봐요.

#### 세부 평가 기준
- API 미연동(더미/하드코딩): 0점이에요.
- API 부분 연동(핵심 일부만 실데이터): 10점이에요.
- API 전면 연동(목록/상세/작성 등 관련 흐름 전부): 15점이에요.
- 예외/에러 응답 처리가 된 경우(4xx/5xx/타임아웃/빈 데이터): 가산 +5점이에요.


## 02. 안정성(크래시/ANR) (20점)
#### 채점 방법
- Release 빌드를 사용하며 ANR과 크래시가 발생하는지 확인해요.

#### 세부 평가 기준
- 크래시나 ANR이 발생하면 이 항목은 0점이에요.


## 03. 기능 동작 완성도 (20점)
#### 채점 방법
- Release 기준으로 APK를 추출해 주세요. 기능명세서에 따라 앱을 실행하며 기능을 확인해요.

#### 세부 평가 기준
- 기능명세서를 기준으로 평가해요.
- 메인 기능이 구현되지 않은 경우에는 0점이에요.
- 메인 기능은 구현됐지만 추가적인 기능들을 구현하지 못한 경우에는 10점이에요.
- 모든 기능을 구현했지만 하드코딩이 된 부분들이 존재하는 경우에는 15점이에요.
- 모든 기능을 정상적으로 구현한 경우에는 20점이에요.
- configurationChange에 대응하지 않으면 5점을 감점해요.


## 04. 코드 가독성 (20점)
#### 채점 방법
- 전체 코드의 흐름과 의도가 잘 전달되는지 살펴봐요.

#### 세부 평가 기준
- 의도 전달력: 10점이에요.
- 아키텍처 일관성: 5점이에요.
- 복잡도: 5점이에요.


## 05. UIㆍ앱 완성도 (25점)
#### 채점 방법
- Release 빌드에서 Figma·기획과 화면이 일치하는지, 입력 처리와 동작이 적절한지 확인해요.

#### 세부 평가 기준
- 기획/Figma와의 전반적 일치 확인: 10점이에요.
- 입력값 대응(숫자/길이/공백 등): 5점이에요.
- 기기별 화면 크기 대응: 5점이에요.
- 기본 접근성/터치 피드백(터치 영역, 라벨, 포커스): 5점이에요.
- 상태 화면 구현시(로딩ㆍ빈 상태ㆍ에러 안내): 가산 +5점이에요.
