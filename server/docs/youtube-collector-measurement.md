# YouTube 수집기 실측 결과 (2026-11-21)

수집기(`src/youtube-collector/`)를 실제 YouTube Data API로 돌려, 채널당 100개를 채우는 데 `search.list`가 몇 회 필요한지 잰 기록이다. 설계와 한도는 [decisions/0003-youtube-collector.md](decisions/0003-youtube-collector.md) 참고.

## 결론

- 채널 9개 × 100개 = **900개를 채우는 데 `search.list` 32회**가 들었다. 일일 한도 100회의 32%다.
- 채널당 3~4회면 100개가 찼다. 검색 1회당 평균 34개가 조건을 통과했다.
- 실행 전체 상한 60회, 채널당 상한 6회는 이 결과 기준으로 여유가 있다. 올릴 근거는 없다.
- 통과한 영상이 채널 성격에 맞는지(품질)는 이 실측으로 알 수 없다.

## 조건

| 항목 | 값 |
| --- | --- |
| 실행 방식 | `--dry-run` (YouTube는 실제 호출, 서버에는 보내지 않음) |
| 채널·검색어 | [youtube-collector-channels.sample.json](youtube-collector-channels.sample.json) (기획 편성표 제안 검색어, 팀 확정 전) |
| 시작 상태 | 모든 채널의 활성 영상 0개 (최초 채우기) |
| 채널당 목표 | 100개 |
| 길이 필터 | 600~7,200초 (10분~2시간, 경계 포함) |
| 그 외 필터 | `status.embeddable=true`, `status.privacyStatus=public` |
| 검색 상한 | 실행 전체 60회 (채널당 상한은 이 실측 뒤에 추가됨) |
| 수집기 버전 | 커밋 `57f5d06` 직전 작업본 (채널당 상한 추가 전) |

### 요청 형태

API 키는 URL이 아니라 `X-Goog-Api-Key` 헤더로 보낸다. 모든 검색은 첫 페이지였다(`pageToken` 없음).

```
GET https://www.googleapis.com/youtube/v3/search
  ?part=snippet&type=video&q=<검색어>
  &regionCode=KR&relevanceLanguage=ko
  &videoEmbeddable=true&videoSyndicated=true
  &videoDuration=<medium|long>&maxResults=50
  &fields=items/id/videoId,nextPageToken

GET https://www.googleapis.com/youtube/v3/videos
  ?part=snippet,contentDetails,status&id=<검색 한 번에서 처음 본 ID, 최대 50개>
```

`videoDuration`의 `medium`은 4~20분, `long`은 20분 초과다. 하한이 10분이라 10~20분 영상을 얻으려면 `medium`도 검색해야 한다.

| **합계** | | **32** | **1,579** | **1,089** | **69%** | **34.0** | **900/900** |

- **새 후보**: 검색으로 받은 영상 ID 중 이번 실행에서 처음 본 것. 다른 채널에서 이미 나온 ID는 빠진다.
- **통과**: 새 후보 중 길이·임베드·공개 조건을 모두 만족한 것. 100개를 넘는 분은 저장 대상에서 제외된다.
- 종료 사유는 `done`(더 찾을 필요 없음), 재검증 실패는 0건이다.
- `videos.list`는 검색 한 번마다 한 번씩, 총 32회 호출됐다(32유닛, 일일 10,000유닛 중).

### 읽을 때 주의할 점

- **쿼리별 후보·통과 수는 없다.** 수집기가 채널 합계만 기록한다. 쿼리 순서는 코드상 고정(검색어마다 M → L, 첫 페이지를 모두 본 뒤 다음 페이지)이라 위 목록은 정확하지만, M과 L 중 어느 쪽 통과율이 높은지는 알 수 없다.
- **세 번째 검색어는 어느 채널에서도 쓰이지 않았다.** 검색어 2개에서 100개가 다 찼다.
- **검색 결과는 호출마다 조금 달라진다.** 같은 날 먼저 돌린 채널 1 단독 실측에서는 같은 쿼리 3개로 새 후보 148개 중 106개가 통과했고, 전체 실측에서는 100개였다.
- **"경제 5분", "5분 레시피", "1분 뉴스"** 같은 검색어도 통과율은 다른 검색어와 비슷했다. 다만 10분 이상 영상이 그 검색어의 의도에 맞는지는 제목을 확인하지 않았다.

## 할당량 사용

| 실행 | `search.list` | 누계 |
| --- | --- | --- |
| 채널 1 단독 | 3회 | 3회 |
| 9개 채널 전체 | 32회 | 35회 |

`search.list`는 전용 버킷으로 하루 100회이고, 태평양 시간 자정(11월 기준 한국 시간 17:00)에 초기화된다.

## 확인하지 못한 것

- 통과한 영상의 품질과 채널 적합성.
- M과 L 구간별 통과율.
- 이미 영상이 차 있는 상태에서의 보충 실행. 같은 쿼리의 앞 페이지를 다시 받으므로 최초 채우기보다 검색당 새 후보가 적을 것으로 예상하지만 재지 않았다.
- 실제 서버 동기화. 서버 내부 API가 아직 없다.
- 채널당 상한(6회)을 추가한 뒤의 실제 호출. 실측에서 채널당 최대 4회였으므로 같은 조건이면 결과는 같다.

## 다시 재려면

`server/.env.local`에 `YOUTUBE_API_KEY`를 넣고 `server/`에서 실행한다. 전체 실행은 약 32회를 쓴다.

```bash
pnpm build
pnpm collect:youtube --dry-run --channels-file=docs/youtube-collector-channels.sample.json

# 한 채널만
pnpm collect:youtube --dry-run --channels-file=docs/youtube-collector-channels.sample.json --channel=1
```
