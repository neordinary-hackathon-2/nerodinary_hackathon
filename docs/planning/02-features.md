# 02. MVP 기능 목록 (기능 최적화 30)

> 원칙: 핵심 기능만으로 주요 과업을 끝까지 수행 가능해야 함 / 부가 기능은 분리 / 확정 후 변경 최소화
> 로그인·회원가입은 꼭 필요한 경우에만 (기본: 제외)
> ⚠️ 직무별 심사 기준상 **API 미연동·하드코딩은 0점**, **로컬호스트는 0점** → 영상 목록은 서버 DB에서 API로 내려준다

## 컨셉
- **채널 1개 = 카테고리 1개.** 채널 이름이 곧 카테고리다 (예: 예능, 금융, 뉴스, 스포츠 …). 사용자는 영상을 고르지 않고, TV 리모컨으로 **다음 채널(카테고리)로만** 넘긴다 (제약)
- 한 채널을 틀면 그 카테고리의 영상이 재생된다 (유튜브 플레이어 임베드)
- 채널(카테고리) 수는 서버 데이터로 관리하며 개수는 열린 질문(05 문서). 권장은 5~7개 (너무 많으면 고르는 피로가 되살아남)
- 시간 제약은 두지 않는다 (식사 20분 동안 자유롭게 시청)
- 톤: 투박한 레트로 TV + 리모컨 (사이버 흡연실 같은 감성), 랜덤·엉뚱한 연출

## 채널 편성표 (제안 — 팀 확정 전)

**선정 기준**: ① 밥 먹으며 보기 좋은 길이·분위기 ② 채널끼리 장르 낙차가 커서 넘길 때 엉뚱한 재미 ③ 유튜브에서 영상을 쉽게 모을 수 있음

| 채널 | 이름(카테고리) | 슬로건(화면 자막) | 역할 | 시드 검색 키워드(서버·PM 참고) |
|---|---|---|---|---|
| CH 05 | 예능 | "웃다 체하지 마세요" | 가벼운 웃음, 기본 채널 | 예능 클립, 웃긴 모음, 레전드 장면 |
| CH 07 | 금융 | "밥상에서 갑자기 재테크" | 낙차용 엉뚱 채널 | 재테크 쉽게, 경제 5분, 주식 기초 |
| CH 09 | 뉴스 | "오늘 일을 밥값 시간에" | 정보형, 현실감 | 뉴스 요약, 오늘의 이슈, 1분 뉴스 |
| CH 11 | 먹방 | "남이 먹는 걸 보며 먹기" | 식사 상황과 직결 | 먹방, 라면 먹방, ASMR 식사 |
| CH 13 | 동물 | "힐링 한 숟갈" | 부담 없는 휴식 | 고양이 영상, 강아지 모음, 동물 구조 |
| CH 15 | 음악 | "수저 내려놓고 감상" | 분위기 전환 | 라이브 클립, 플레이리스트, 뮤직비디오 |
| CH 17 | 홈쇼핑 | "지금 안 사면 밥 식어요" | 가장 엉뚱한 반전 채널 (TV 느낌 극대화) | 홈쇼핑 방송 클립, 쇼호스트 멘트 모음, 홈쇼핑 레전드 |

- **편성 원칙**: 홀수 번호(5·7·9…)로 옛날 TV 채널 번호 느낌을 낸다. 번호 간격은 디자인 연출용이며 서버에는 `order`(1~7)로 저장
- **후보 풀(교체용)**: 심야괴담(호불호 있음), 스포츠 하이라이트, 요리 레시피, 브이로그, 게임 하이라이트
- **채널 순서 의도**: 가벼운 채널(예능) → 낙차(금융) → 현실(뉴스) → 식사(먹방) → 휴식(동물·음악) → 반전(홈쇼핑) 순으로 배치해, 넘길 때마다 분위기가 바뀐다
- **영상 기준**: 길이 3~10분 클립 위주(식사 20분 동안 채널을 여러 번 돌릴 수 있게). 퍼가기가 막힌 영상은 제외하고 채널당 8~10개 시드
- **채널 데이터 필드**: 번호, 이름, 슬로건, 대표 색상, 아이콘 (F1 응답에 포함)

## MVP (필수)
| ID | 기능 | 해소하는 Pain Point | 우선순위 | 필요한 데이터 | 데이터가 필요한 이유 | 담당 확인 |
|---|---|---|---|---|---|---|
| F1 | 채널(카테고리) 목록 조회: 카테고리별 채널을 서버에서 받아옴 | 선택지가 무한함 → 소수의 카테고리로 제한 | 1 | 채널=카테고리(id, 이름, 번호, 아이콘/색) | 채널을 서버 데이터로 관리해야 API 연동으로 인정됨 | 서버 / Web |
| F2 | 채널 영상 재생: 채널을 켜면 그 채널의 영상 1개를 유튜브 플레이어로 재생 | 고르지 않고 바로 시청 | 1 | 영상(id, 채널id, 유튜브 링크/ID, 제목) | 채널별로 재생할 영상 링크가 필요함 | 서버 / Web |
| F3 | 채널 넘기기(제약): 리모컨 버튼으로 **다음 채널로만** 이동 (이전·직접 선택 불가) | 비교·탐색 없이 흘러가며 봄 | 1 | 채널 순서(번호) | 다음 채널을 결정하려면 순서가 필요함 | Web |
| F4 | 랜덤 연출: 채널 전환 때 지지직/노이즈 등 TV 효과, 영상은 채널 내 랜덤 선택 | 매번 다른 우연한 만남(재미) | 2 | 채널별 영상 풀 | 랜덤 선택에 쓸 후보 영상 여러 개 | 서버 / Web |
| F5 | 앱 실행(웹뷰): iOS·Android 앱에서 웹을 띄워 동일하게 동작 | 심사 요건(APK·앱 연결 완성도) | 1 | - | - | App |

## 부가 기능 (시간 남으면)
| ID | 기능 | 제외해도 되는 이유 |
|---|---|---|
| X1 | 오늘 시청 기록(채널 시청 로그 저장) | 핵심 과업(채널 돌려 보기)과 무관 |
| X2 | 결과 공유 / "오늘의 채널" 이미지 | 발표 임팩트용, 핵심 과업과 무관 |
| X3 | 리모컨 진동·사운드 효과 | 연출 보강 |
| X4 | 스플래시 이미지 (앱) | 가산점 5점, 시간 남으면 |

## 제외한 것 (의도적으로 안 만드는 것)
- 로그인/회원가입: 제외 (사용자 구분이 필요 없음)
- 실시간 통신(Socket/SSE): 제외
- 영상 검색 / 이전 채널로 돌아가기 / 영상 직접 선택: 제외 (제약 컨셉에 반함)
- 추천 알고리즘: 제외 (랜덤으로 대체)
- 데스크톱 전용 레이아웃: 제외 (모바일 뷰 고정, 데스크톱은 양옆 여백에 로고)

## 주요 과업 시나리오 (사용자가 끝까지 해내는 흐름)
1. 앱/웹에 접속하면 TV가 켜지고 1번 채널 영상이 자동 재생된다
2. 리모컨의 "다음 채널" 버튼을 누르면 다음 채널(2번, 3번…)로 넘어가고 해당 채널 영상이 재생된다
3. 마지막 채널 다음에는 1번 채널로 돌아간다 (순환). 사용자는 20분 동안 이렇게 보며 식사한다

## 예외 · 빈 상태 · 에러 (필수 확인)
| 기능 | 빈 상태 | 에러 | 로딩 |
|---|---|---|---|
| F1 채널 목록 | 채널이 0개: "방송 준비 중" 화면 | 서버 오류: "신호가 약해요" + 다시 시도 | 스켈레톤 (TV 화면 틀) |
| F2 영상 재생 | 채널에 영상이 없음: "방송 없음" 컬러바 화면 | 유튜브 재생 불가(삭제·비공개): 자동으로 같은 채널의 다른 영상 | 노이즈 화면 |
| F5 앱 | - | 웹에서만 되는 기능은 앱에서 안내 메시지 표시 (미안내 시 건당 감점) | 스플래시 |
