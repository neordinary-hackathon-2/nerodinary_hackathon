# 1. 시간대별 가이드

> ⏰ **제출 마감 11.22 · 07:30**
> 07:20부터 프로젝트를 제출해 주세요. 발표 준비 중에도 07:30 제출 마감을 지켜 주세요.


## 01. 16:40—19:00 — 아이디어와 초기 세팅
- 인프라를 구축해 주세요.
  - Git을 설정하고 협업 전략을 정해 주세요.
  - 충돌을 줄일 수 있도록 개발 범위를 나눠 주세요.
  - AWS 등을 활용해 CI/CD 파이프라인을 구성해 주세요. 설정이 어렵다면 우선 배포 가능한 상태를 만들어 주세요.
- 아이디어가 확정되면 DB를 설계해 주세요.
  - 디자인이 완성되기 전에도 전체적인 구조를 먼저 정리해 주세요.
  - 핵심 기능을 중심으로 설계하고 부가 기능은 우선순위에 따라 결정해 주세요.
  - 회원 관련 테이블처럼 먼저 설계할 수 있는 부분은 미리 진행해 주세요.


## 02. 19:00—05:00 — 프로젝트 개발
- 디자인이 구체화되는 흐름에 맞춰 DB의 세부 구성을 완성해 주세요.
- API 시그니처를 작성해 주세요.
  - API 응답 형식을 통일하고 에러 처리를 준비해 주세요.
  - Swagger에 모든 API를 미리 명세해 주세요.
- 핵심 API부터 구현해 주세요.
  - 구현 예정인 API를 먼저 명세하고 개발 중 변경 사항을 반영해 주세요.
  - 구현한 API는 프론트엔드 팀과 함께 순차적으로 연동해 주세요.
  - 연동이 지연되지 않도록 배포를 먼저 완료해 주세요.
- 로그인은 가능한 한 구현 범위에서 제외해 주세요.


## 03. 05:00—07:40 — 최종 점검과 발표 준비
- API 구현과 연동을 마무리해 주세요.
- 오류를 확인하고 수정해 주세요.
  - Swagger로 심사하므로 정상 요청의 동작을 먼저 검증하고, 잘못된 요청에 대한 기본 예외처리도 확인해 주세요.

# 2. 유의사항

1. 심사를 위해 클라우드 환경에 배포해 주세요.
2. 심사자가 접근할 수 있는 배포 URL을 제공해 주세요.
3. Swagger, Postman 등의 API 명세서를 제출해 주세요.
4. 인프라 구성도와 ERD를 제출해 주세요.
5. 전역 예외처리를 적용하고 기본 응답·에러 코드(200/201/400/404/500)를 구분해 주세요.
6. 관심사 분리(SoC)를 적용해 주세요.

# 3. 심사기준

**기본 총점 100점**



## 01. 인프라 및 DB 구성 (30점)
#### 채점 방법
- 인프라 구성도와 ERD를 제출해 주세요. 이를 바탕으로 WAS와 파일 업로드 등의 구성을 살펴봐요.
- 인프라 구성도와 ERD를 제출하지 않으면 이 항목은 0점으로 평가해요.

#### 세부 평가 기준
- 로컬 호스트 환경이면 이 항목은 0점이에요.
- 인프라 구성과 ERD 설계는 10점이에요.
- WAS와 DB를 분리하면 5점이에요.
- CI/CD 파이프라인을 구축하면 5점이에요.
- 기본 보안 설정은 총 10점이며, 아래 항목으로 나누어 평가해요.
  - 민감정보를 안전하게 관리하고 외부 노출을 방지하면 3점이에요.
  - DB 포트를 외부에 불필요하게 노출하지 않으면 2점이에요.
  - HTTPS를 적용하면 2점이에요.
  - 불필요한 서버 포트가 공개되지 않도록 방화벽·보안그룹을 설정하면 3점이에요.
- 인프라 구성도와 ERD는 새벽 4시까지 제출해 주세요. API를 연동할 수 있도록 이 시간까지 인프라 구성을 완료해 주세요.
- 인프라 구성도는 [구글폼](https://forms.gle/sMLeoNTrPdqUQofD8)에 제출해 주세요.
- 폼 제출 시각이 새벽 4시 이후이면 이 항목은 0점으로 평가해요.


## 02. 코드 품질 (15점)
#### 채점 방법
- API 명세서와 심사자가 접근할 수 있는 배포 URL을 제공해 주세요. 제공하지 않으면 이 항목은 0점으로 평가해요.
- 코드를 확인할 수 있는 저장소 URL도 제공해 주세요. 제공하지 않으면 이 항목은 0점으로 평가해요.

#### 세부 평가 기준
- 관심사가 분리되어 있지 않으면 이 항목은 0점이에요.
- 중복 코드를 줄이고 공통 로직을 적절히 재사용하면 5점이에요.
- 환경별 설정을 분리하고 설정값을 외부화해 관리하면 5점이에요.
- 관심사가 잘 분리되어 있으면 5점이에요.


## 03. API 정상 동작 (35점)
#### 채점 방법
- API 명세서와 심사자가 접근할 수 있는 배포 URL을 제공해 주세요. 제공하지 않으면 이 항목은 0점으로 평가해요.
- 테스트가 어렵거나 Internal Server Error(500)가 발생하면 감점될 수 있어요.
- 전체 API 중 오류가 발생한 API의 비율을 기준으로 평가해요.

#### 세부 평가 기준
- 명세에 작성된 API가 정상 동작하는 비율에 따라 0~30점을 부여해요.
- Swagger에 바로 호출할 수 있는 예시를 작성한 비율에 따라 최대 5점을 부여해요.


## 04. API 예외처리 (20점)
#### 채점 방법
- API 명세서와 심사자가 접근할 수 있는 배포 URL을 제공해 주세요. 제공하지 않으면 이 항목은 0점으로 평가해요.
- 쿼리 스트링이나 HTTP 요청 본문에 잘못된 값을 넣어 예외처리를 확인해요.
- 기대한 동작과 다르면 감점될 수 있어요.

#### 세부 평가 기준
- 전역 예외처리가 없으면 이 항목은 0점이에요.
- 전역 예외처리를 적용하면 10점이에요.
- 전역 예외처리와 기본 응답·에러 코드(200/201/400/404/500)를 적절하게 처리하면 추가로 10점이에요.
