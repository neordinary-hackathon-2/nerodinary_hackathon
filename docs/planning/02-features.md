# 02. MVP 기능 목록 (기능 최적화 30)

> 원칙: 핵심 기능만으로 주요 과업을 끝까지 수행 가능해야 함 / 부가 기능은 분리 / 확정 후 변경 최소화
> 로그인·회원가입은 꼭 필요한 경우에만 (기본: 제외)
> ⚠️ 직무별 심사 기준상 **API 미연동·하드코딩은 0점**, **로컬호스트는 0점** → 영상 목록은 서버 DB에서 API로 내려준다

## 컨셉
- **채널 1개 = 카테고리 1개.** 채널 이름이 곧 카테고리다 (예: 예능, 금융, 뉴스, 스포츠 …). 사용자는 영상을 고르지 않고, TV 리모컨의 **채널 ▲(다음 채널)** 또는 **숫자 키(0~9, 한 자리 직접 입력)**로 채널을 옮긴다. 이전 채널(▼)은 없다 (제약은 일부만 허용)
- 한 채널을 틀면 그 카테고리의 영상이 재생된다 (유튜브 플레이어 임베드)
- **TV는 처음에 꺼져 있다.** 웹 브라우저는 소리 있는 자동재생을 막고(자동재생은 음소거일 때만 가능), 사용자가 화면을 한 번 조작한 뒤에야 소리가 허용된다. 그래서 접속하면 꺼진 TV가 보이고, 리모컨의 **전원 버튼을 눌러 TV를 켜면** 1번 채널(예능) 영상이 소리와 함께 재생된다 (F7, 11.21 변경: 켰을 때 시작 채널은 0번 컬러바가 아니라 1번. 0번 컬러바로 시작하면 데이터 오류처럼 보이기 때문). 전원 버튼은 **한 번 누르면 켜지고, 다시 누르면 꺼지는 토글**이다. 끄면 영상이 멈추고 꺼진 TV 화면으로 돌아간다 (11.21 결정)
- 유튜브 영상은 16:9인데 세로 모바일 화면의 TV 틀 안에서는 작아 보인다 → TV 화면을 16:9로 맞추고, 크게 보고 싶으면 **유튜브 플레이어 기본 전체화면 버튼**을 쓰게 한다 (F6, 직접 만들지 않고 iframe의 `allowfullscreen`으로 제공). 전체화면 중에는 플레이어만 보이므로 리모컨은 전체화면을 해제한 뒤 쓴다
- 채널(카테고리) 수는 서버 데이터로 관리하며 **채널 번호는 한 자리(0~9), 총 10개로 확정**한다. **0번은 영상 없는 컬러바 채널**이고, 1~9번이 카테고리 9개다. 9번 다음은 0번으로 순환한다. 리모컨 숫자 키패드(0~9)와 채널이 1:1로 대응돼 직관적이고, 화면 표기도 한 자리로만 보인다 (예: CH 3 · 먹방)
- 시간 제약은 두지 않는다 (식사 20분 동안 자유롭게 시청)
- 톤: 투박한 레트로 TV + 리모컨 (사이버 흡연실 같은 감성), 랜덤·엉뚱한 연출

## 채널 편성표 (제안 — 팀 확정 전)

**선정 기준**: ① 밥 먹으며 보기 좋은 길이·분위기 ② 채널끼리 장르 낙차가 커서 넘길 때 엉뚱한 재미 ③ 유튜브에서 영상을 쉽게 모을 수 있음

| 채널 | 이름(카테고리) | 슬로건(화면 자막) | 역할 | 시드 검색 키워드(서버·PM 참고) |
|---|---|---|---|---|
| CH 0 | 컬러바 | "잠시 후 방송이 시작됩니다" | 영상 없는 컬러바 채널(방송 없음 화면과 같은 연출). 켰을 때 시작 채널은 아님 | - (영상 시드 없음) |
| CH 1 | 예능 | "웃다 체하지 마세요" | 가벼운 웃음 | 예능 클립, 웃긴 모음, 레전드 장면 |
| CH 2 | 금융 | "밥상에서 갑자기 재테크" | 낙차용 엉뚱 채널 | 재테크 쉽게, 경제 5분, 주식 기초 |
| CH 3 | 뉴스 | "오늘 일을 밥값 시간에" | 정보형, 현실감 | 뉴스 요약, 오늘의 이슈, 1분 뉴스 |
| CH 4 | 먹방 | "남이 먹는 걸 보며 먹기" | 식사 상황과 직결 | 먹방, 라면 먹방, ASMR 식사 |
| CH 5 | 요리 | "오늘 반찬은 구경으로" | 식사 연관, 눈요기 | 자취 요리, 5분 레시피, 요리 대결 |
| CH 6 | 동물 | "힐링 한 숟갈" | 부담 없는 휴식 | 고양이 영상, 강아지 모음, 동물 구조 |
| CH 7 | 음악 | "수저 내려놓고 감상" | 분위기 전환 | 라이브 클립, 플레이리스트, 뮤직비디오 |
| CH 8 | 스포츠 | "밥 먹다 응원 시작" | 에너지 전환 | 경기 하이라이트, 야구·축구 명장면, 스포츠 레전드 |
| CH 9 | 홈쇼핑 | "지금 안 사면 밥 식어요" | 가장 엉뚱한 반전 채널 (TV 느낌 극대화) | 홈쇼핑 방송 클립, 쇼호스트 멘트 모음, 홈쇼핑 레전드 |

- **편성 원칙**: 채널 번호 = 리모컨 숫자 키(0~9)와 1:1 대응. 번호는 한 자리로만 입력·표시하며, 서버에는 카테고리 채널을 `order`(1~9)로 저장해 화면 번호와 동일하게 쓰고, 0번 컬러바는 영상이 없는 클라이언트 고정 화면이다 (연출용 별도 번호 없음). 숫자 키를 누르면 해당 번호 채널로 바로 이동한다 (11.21 결정: 다음 채널 제약을 일부 완화)
- **후보 풀(교체용)**: 심야괴담(호불호 있음), 브이로그, 게임 하이라이트
- **채널 순서 의도**: 가벼운 채널(예능) → 낙차(금융) → 현실(뉴스) → 식사(먹방·요리) → 휴식(동물·음악) → 에너지(스포츠) → 반전(홈쇼핑) 순으로 배치해, 넘길 때마다 분위기가 바뀐다
- **영상 기준 (11.21 결정)**: 길이 **하한 10분 ~ 상한 2시간**인 영상만 수집한다. 퍼가기가 막힌 영상은 제외한다
- **영상 수집량 (11.21 결정)**: 유튜브에서 **하루 10개씩 크롤링**하고, DB에는 **하루에 100개가 쌓인다**. 수집은 매일 반복되므로 영상 DB는 날마다 늘어난다. (참고: 카테고리 채널이 1~9번 9개(0번 컬러바 제외)라 "10개 × 채널 수"와 100개가 맞지 않는다. 채널별 수집 개수 배분은 서버와 확인 필요)
- **영상 수집 방식 (YouTube Data API, 참고: `docs/youtube-data-api.md`)**: 채널별 시드 키워드로 `search.list`(후보 발견) → `videos.list`(길이·임베드·공개 상태 검증) 순으로 수집한다. 0번 컬러바는 수집 대상이 아니다
  - `search.list` (`part=snippet`, `type=video`)에서 가져올 값: 영상 ID(`id.videoId`), 제목(`snippet.title`), 썸네일 URL(`snippet.thumbnails.medium.url`), 원본 제작자명(`snippet.channelTitle`, 선택), 공개 일시(`snippet.publishedAt`, 선택)
  - `videos.list` (`part=snippet,contentDetails,status`)에서 검증할 값: 재생 길이(`contentDetails.duration`, ISO 8601을 초로 변환해 600~7200초만 통과), 임베드 허용(`status.embeddable=true`), 공개 상태(`status.privacyStatus=public`)
  - 길이 필터: 검색은 `videoDuration`을 `medium`(4~20분)과 `long`(20분 초과)로 나눠 하고, 정확한 길이는 `videos.list`로 거른다
  - **페이지 호출 횟수 제한**: `search.list`는 호출 1회당 쿼터 100유닛이라 `pageToken`으로 많이 넘기면 일일 할당량에 부담이 된다. 채널당 호출(페이지 넘김 포함)에 상한 횟수를 두고, 도달하면 그때까지 모은 후보로 진행한다 (상한 수치는 서버와 확정)
  - 수집 실패·할당량 초과 시 마지막 정상 후보를 유지하고, 하루 한 번 기존 영상을 재검증해 재생 불가 영상은 비활성화한다
  - 제외 API: `channels.list`, `playlistItems.list`, `videoCategories.list` (특정 제작자 등록·YouTube 공식 분류를 쓰지 않으므로 MVP 제외)
- **영상 데이터 필드**: 유튜브 영상 ID(고유값, 중복 제외·upsert 기준), 채널 id, 제목, 썸네일 URL, 재생 길이(초), 활성 여부, 마지막 갱신 시각(`lastRefreshedAt`). 시청 URL·iframe URL은 저장하지 않고 영상 ID로 만들며, 썸네일 이미지 파일은 저장하지 않는다
- **채널 데이터 필드**: 번호, 이름, 슬로건, 대표 색상, 아이콘 (F1 응답에 포함)

## MVP (필수)
| ID | 기능 | 해소하는 Pain Point | 우선순위 | 필요한 데이터 | 데이터가 필요한 이유 | 담당 확인 |
|---|---|---|---|---|---|---|
| F1 | 채널(카테고리) 목록 조회: 카테고리별 채널을 서버에서 받아옴 | 선택지가 무한함 → 소수의 카테고리로 제한 | 1 | 채널=카테고리(id, 이름, 번호, 아이콘/색) | 채널을 서버 데이터로 관리해야 API 연동으로 인정됨 | 서버 / Web |
| F2 | 채널 영상 재생: 채널을 켜면 그 채널의 영상 1개를 유튜브 플레이어로 재생 | 고르지 않고 바로 시청 | 1 | 영상(id, 채널id, 유튜브 링크/ID, 제목) | 채널별로 재생할 영상 링크가 필요함 | 서버 / Web |
| F3 | 채널 이동(제약 일부 허용): 리모컨 **채널 ▲로 다음 채널**, 또는 **숫자 키 0~9(한 자리)로 해당 채널 직접 이동**. 채널 ▼(이전)는 없음. 없는 번호는 무시, 현재 채널과 같은 번호는 아무 일 없음 | 비교·탐색 없이 흘러가며 보되, 보고 싶은 채널로 바로 갈 수 있는 자유는 남김 | 1 | 채널 순서(번호) | 다음 채널 결정·번호로 채널 찾기에 번호가 필요함 | Web |
| F4 | 랜덤 연출: 채널 전환 때 지지직/노이즈 등 TV 효과, 영상은 채널 내 랜덤 선택. **채널별 영상은 접속(세션) 동안 고정**: 채널을 넘겼다가 다시 돌아오면 같은 영상이 나온다 (11.21 결정) | 매번 다른 우연한 만남(재미) | 2 | 채널별 영상 풀 | 랜덤 선택에 쓸 후보 영상 여러 개 | 서버 / Web |
| F5 | 앱 실행(웹뷰): iOS·Android 앱에서 웹을 띄워 동일하게 동작 | 심사 요건(APK·앱 연결 완성도) | 1 | - | - | App |
| F7 | TV 전원 켜기/끄기(토글): 접속 시 TV는 꺼진 상태(검은 화면)이고, 리모컨 전원 버튼을 누르면 켜지며 채널 목록 조회(F1) → **1번 채널 영상이 소리와 함께 재생됨**(시작은 0번 컬러바가 아닌 1번). 사용자는 채널 ▲ 또는 숫자 키로 0번 컬러바를 포함한 다른 채널로 이동. 전원 버튼은 항상 활성이며, 켠 뒤 다시 누르면 TV가 꺼진다(영상 정지·꺼진 화면). 꺼진 상태에서는 전원만 동작하고 나머지 버튼은 비활성. 다시 켜면 켜기와 같은 순서로 1번 채널부터 시작한다(영상 기억 여부는 확인 필요) | 브라우저의 소리 있는 자동재생 차단 → 사용자 조작으로 소리 재생 허용 | 1 | - (클라이언트 기능, 서버 데이터 없음) | 서버 필요 없음 | Web / App |
| F6 | 플레이어 전체화면: 유튜브 iframe 임베드에 `allowfullscreen`을 켜서 플레이어 기본 전체화면 버튼 사용. 앱이 별도 버튼·오버레이를 만들지 않음. 전체화면을 해제하면 S2로 복귀 | 세로 화면에서 16:9 영상이 작아 보이는 문제 → 몰입감 확보 | 2 | - (플레이어 기본 기능, 서버 데이터 없음) | 서버 필요 없음 | Web / App |
| F8 | 영상 새로고침("먹기 싫어" 버튼): 리모컨 새로고침 버튼을 누르면 **지금 보고 있는 채널의 영상만** 같은 채널의 다른 영상으로 바꾼다. 다른 채널의 영상은 그대로. 바뀐 영상이 그 채널의 새 고정 영상이 되어, 채널을 넘겼다 돌아와도 바뀐 영상이 나온다. 직전에 본 영상은 다시 뽑지 않는다 | "뭐 먹을지 다 차려주되, 싫으면 거르는" 자유 → 고르지 않고도 마음에 안 드는 영상은 피함 (선택 부담 없이 거부만 가능) | 1 | 채널별 영상 풀 (F4와 같은 데이터) | 같은 채널의 다른 영상을 뽑을 후보가 여러 개 필요함 | Web / App |
| F9 | 채널 편성표 팝업: 헤더 ? 아이콘을 누르면 채널 0~9번의 번호·카테고리·슬로건 표를 팝업으로 보여준다 (닫기 ×). 안내 문구 "채널 ▲ 또는 숫자 키(0~9)로 이동할 수 있어요" | 어떤 채널이 있는지 몰라 헤매는 것 방지 (고르게 하지 않고 안내만) | 2 | 채널 목록 (F1과 같은 데이터) | 팝업 내용을 서버 채널 데이터로 표시해야 API 연동으로 인정됨 | Web / App |

- 로그인/회원가입: 제외 (사용자 구분이 필요 없음)
- 실시간 통신(Socket/SSE): 제외
- 영상 검색 / 채널 ▼(이전 채널 버튼) / 영상 직접 선택: 제외 (제약 컨셉에 반함). 단 숫자 키로 채널 번호를 눌러 이동하는 것은 허용
- 추천 알고리즘: 제외 (랜덤으로 대체)
- 데스크톱 전용 레이아웃: 제외 (모바일 뷰 고정, 데스크톱은 양옆 여백에 로고)

## 주요 과업 시나리오 (사용자가 끝까지 해내는 흐름)
1. 앱/웹에 접속하면 TV는 꺼져 있다. 리모컨의 전원 버튼을 눌러 TV를 켜면 1번 채널(예능) 영상이 소리와 함께 재생되고, 채널 ▲나 숫자 키로 다른 채널로 넘어간다
2. 리모컨의 "다음 채널" 버튼을 누르면 다음 채널(1번에서는 2번, 3번…)로, 숫자 키(0~9)를 누르면 그 번호 채널로 바로 넘어가고 해당 채널 영상이 재생된다
3. 마지막 채널(9번) 다음에는 0번 컬러바 채널로 돌아간다 (순환). 사용자는 20분 동안 이렇게 보며 식사한다
4. 보던 영상이 마음에 안 들면 리모컨 새로고침 버튼("먹기 싫어")을 누른다. 지금 채널의 영상만 같은 채널의 다른 영상으로 바뀌고, 이후 그 채널로 돌아오면 바뀐 영상이 나온다
5. (선택) 영상을 크게 보고 싶으면 유튜브 플레이어의 전체화면 버튼을 누른다. 전체화면을 해제하면 S2로 돌아와 리모컨으로 채널을 옮긴다
