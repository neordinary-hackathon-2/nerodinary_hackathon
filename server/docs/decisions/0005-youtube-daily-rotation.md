# 0005. 채널당 100개를 유지하면서 하루 10개씩 최근 영상으로 교체한다

- 상태: 결정됨 (2026-11-22)
- 결정자: sychoi
- 범위: `server/src/youtube-collector/`, `server/src/youtube/`
- 바꾸는 결정: [0003](0003-youtube-collector.md)의 재실행 정책 "부족분만 보충"

## 배경

0003의 "부족분만 보충"은 채널이 100개로 차면 검색을 멈춘다. 영상이 삭제·비공개가 되지 않는 한 풀이 바뀌지 않아, 매일 수집기를 돌려도 새 영상이 들어오지 않았다.

## 결정

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 채널당 유지 개수 | 100개 (`TARGET_PER_CHANNEL`). 영상 채널 9개 기준 전체 900개 | 0003 유지 |
| 하루 교체량 | 채널당 10개 (`ROTATE_PER_CHANNEL`) | 10일이면 풀 전체가 한 번 바뀐다 |
| 삭제 기준 | 마지막 재확인 시각이 오래된 순 (`last_refreshed_at`, 같으면 `created_at`, `id`) | 최근에도 재검증된 영상은 보존하고, 오래 재확인하지 못한 영상부터 교체한다. `last_refreshed_at`이 없는 행은 먼저 삭제한다 |
| 삭제 주체 | 서버. sync 처리 끝에 채널당 유지 개수를 넘는 만큼만 지운다 | "채널당 100개 이하"를 서버가 보장한다. 수집기가 요청을 나눠 보내도 안전하다 |
| 새 영상 찾기 | 최근 7일 안에 공개된 영상만 검색 (`FRESH_WINDOW_DAYS`, `search.list`의 `publishedAfter`). 정렬은 관련도순 그대로 | 아래 "지운 영상이 다시 들어오지 않는 조건" |
| 끄는 방법 | `ROTATE_PER_CHANNEL=0` 이면 0003의 "부족분만 보충"과 같다 | 문제가 생기면 배포 없이 되돌린다 |

### 넣은 만큼만 지운다

수집기는 삭제할 영상을 고르지 않는다. 새 영상을 보내면 서버가 유지 개수를 넘는 만큼 오래된 영상을 지운다. 새 영상을 못 찾은 날(검색 결과 없음, 할당량 초과, 검색 실패)에는 넘는 것이 없어 아무것도 지워지지 않는다. 풀이 100개 밑으로 내려가는 것은 영상이 삭제·비공개·임베드 차단된 경우뿐이다.

### 지운 영상이 다시 들어오지 않는 조건

수집기가 "이미 아는 영상"으로 치는 것은 현재 저장된 영상뿐이라, 지운 영상이 검색에 다시 잡히면 새 영상으로 들어온다. 삭제 이력을 따로 두지 않고 검색 기간으로 막는다.

- 영상 하나는 들어온 뒤 100 ÷ 10 = 10일이 지나야 밀려난다(교체가 덜 된 날이 있으면 더 늦다).
- 밀려나는 시점에 그 영상은 공개된 지 10일이 넘었으므로, 최근 7일만 보는 검색에 잡히지 않는다.
- 그래서 `FRESH_WINDOW_DAYS × ROTATE_PER_CHANNEL < TARGET_PER_CHANNEL` 이어야 한다. 수집기는 시작할 때 이 조건을 확인하고 어긋나면 실행하지 않는다.

### 한 번 실행의 흐름 (채널별)

1. 저장된 영상을 재검증한다. 죽은 영상은 삭제 목록에 넣는다(0003과 같다).
2. 모자란 수가 교체량 이하이면 기간 조건 검색으로 최대 10개를 찾는다.
3. 그래도 100개에 모자라면 모자란 만큼만 기간 없는 검색으로 채운다.
4. 모자란 수가 교체량보다 많으면(처음 채울 때 등) 교체하지 않고 기간 없는 검색으로 채우기만 한다.
5. 서버가 저장된 영상 목록을 주지 않으면 교체하지 않는다.

## 내부 API 계약 변경

- `POST /api/internal/youtube/sync` 응답에 `evictedCount`(유지 개수를 넘어 지운 영상 수)를 더했다.
- 서버도 `TARGET_PER_CHANNEL`을 읽는다. 기본값은 `src/youtube/youtube.constants.ts`의 `DEFAULT_TARGET_PER_CHANNEL`을 수집기와 함께 쓴다.
- 요청 형식은 그대로다.

## 실측 (2026-11-22)

최근 7일 조건, 채널별 첫 검색어 하나, `medium`·`long` 한 번씩(`search.list` 18회).

| 채널 | 검색어 | 통과 | 그중 3일 내 | 그중 1일 내 |
| --- | --- | --- | --- | --- |
| 1 예능 | 예능 클립 | 72 | 24 | 11 |
| 2 금융 | 재테크 쉽게 | 85 | 10 | 3 |
| 3 뉴스 | 뉴스 요약 | 64 | 17 | 2 |
| 4 먹방 | 먹방 | 83 | 44 | 9 |
| 5 요리 | 자취 요리 | 68 | 22 | 5 |
| 6 동물 | 고양이 영상 | 52 | 27 | 8 |
| 7 음악 | 라이브 클립 | 60 | 33 | 7 |
| 8 스포츠 | 경기 하이라이트 | 81 | 27 | 13 |
| 9 홈쇼핑 | 홈쇼핑 방송 클립 | 1 | 1 | 0 |

- "3일 내"·"1일 내"는 7일 검색 결과 안에서 센 값이라 하한이다.
- 통과한 영상이 채널 성격에 맞는지는 확인하지 않았다.

## 알려진 한계

- **며칠 지나면 하루 10개를 못 채우는 채널이 생길 수 있다.** 7일 안의 영상을 이미 들인 뒤에는 그날 새로 공개된 영상이 주된 후보다. 위 표의 "1일 내"가 10 미만인 채널이 많다. 못 채운 날은 찾은 만큼만 교체한다. 검색어를 늘리면 후보가 늘어난다.
- **홈쇼핑(9번)은 첫 검색어로 7일간 1개뿐이었다.** 나머지 검색어는 재지 않았다. 지금 검색어로는 거의 교체되지 않는다.
- **기간 없는 채우기 검색으로는 지운 영상이 다시 들어올 수 있다.** 죽은 영상 자리를 메울 때만 쓰이므로 양은 적다.
- **서버의 `TARGET_PER_CHANNEL`을 낮추면 다음 sync 때 초과분이 한꺼번에 지워진다.**
- **할당량:** 채널당 교체용 검색 1~2회가 매일 더 든다(9개 채널 9~18회). 실행당 상한 60회, 채널당 6회 안이다.
- **배포 순서:** 수집기가 `evictedCount`를 필수로 읽으므로 서버를 먼저 배포한다. 서버가 옛 버전이면 수집기가 동기화 실패로 보고한다(영상 저장은 된 상태다).

## 검증

- 수집기 단위 테스트(`collector.spec.ts`의 "하루 교체" 묶음): 꽉 찬 채널의 교체, 저장된 영상 제외, 새 영상이 없거나 할당량이 막힌 날 무변경, 죽은 영상 보충 순서, 처음 채우기에서 교체 안 함, dry-run 보고.
- 서버 삭제 SQL: 자동 테스트는 없다(e2e는 서비스를 가짜로 바꿔 돌린다). 수동으로 두 번 확인했다.
  - 처음: 임시 MySQL 9.3에서 `YoutubeSyncService.sync`를 직접 호출했다. 당시 스키마는 영상 ID 단독 고유 제약이었다. 넘는 만큼만 삭제, `created_at`이 같을 때 `id` 순, 다른 채널 불변, 새 영상 없으면 무삭제, 삭제 목록과 함께 올 때, 나눠 보낼 때.
  - 2026-11-22: 현재 스키마(`(app_channel_id, youtube_video_id)` 복합 고유 제약)의 임시 MySQL 9.3에 `TARGET_PER_CHANNEL=5`로 서버를 띄우고 `POST /api/internal/youtube/sync`를 호출했다. 9개 시나리오 18개 확인이 통과했고 서버 로그 오류는 0건이었다. 스크립트는 일회성이라 저장소에 넣지 않았다.
    1. 목표 개수까지 저장하면 지우지 않는다.
    2. 새 영상 2개가 들어오면 가장 오래된 2개가 지워진다.
    3. 기존 영상만 갱신하면 지우지 않는다.
    4. 같은 영상을 다른 채널에 저장해도 원래 채널은 그대로다.
    5. 초과분은 요청한 채널에서만 지운다.
    6. `removedVideoIds`를 먼저 반영한 뒤 넘는 만큼만 지운다.
    7. 빈 채널에 목표보다 많이 들어오면 목표 개수만 남고, 요청 안에서 앞에 온 영상부터 빠진다.
    8. 같은 요청을 다시 보내도 행이 늘지 않는다.
    9. `seed-config`가 삭제 후 저장 목록을 돌려준다.
- 같은 채널에 `sync`가 동시에 들어오는 경우와 실제 규모(채널당 100개, 50개 묶음 전송)의 삭제는 확인하지 않았다.
- 실제 YouTube·서버를 붙여 이틀 연속 돌려 보는 확인은 하지 않았다.
