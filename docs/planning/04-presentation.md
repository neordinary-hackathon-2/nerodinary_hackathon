## 슬라이드별 보강 내용 (추가)

### 03 해결 방안: 기획 의도 + 제약 일부 허용 논리
- 기획 의도: "고르는 일"을 없애는 게 아니라 "고르는 행위를 채널 돌리기라는 놀이로 바꾼다"
- 제약 일부 허용(11.21 결정)을 한 줄로 설명: 숫자 키(한 자리)는 허용 / 채널 ▼(이전)·영상 직접 선택·검색은 계속 제외 → "고를 수는 있어도 비교·탐색은 못 한다"
- 예상 반박 "숫자 키·새로고침이 있으면 결국 고르는 거 아니냐"에 대한 답을 슬라이드나 백업(B1)에 준비

### 04 MVP 선정: 필수 / 보조 / 요건 구분
- 필수(Pain Point 직결): F1 채널 목록, F2 영상 재생, F3 채널 이동, F8 새로고침
- 필수 보조(기술 제약 대응): F7 전원 켜기/끄기 (브라우저 자동재생 차단 대응)
- 보조: F4 랜덤 연출, F6 전체화면, F9 편성표 팝업
- 요건: F5 앱 실행. 발표에서는 "심사 요건"이라 말하지 않고 "iOS·Android·웹 동일 경험"으로 표현
- 제외: 로그인·검색·채널 ▼·추천 알고리즘 (제약 컨셉에 반함)

### 06 사용자 플로우·화면 구성: 디자인 해석
- "기획 → 디자인 해석" 한 줄: 제약 → 한 자리 번호 리모컨 / 소리 문제 → 꺼진 TV와 전원 버튼 / 선택 부담 → 활성 버튼 최소화
- 디자인 시스템(Retro Pixel: 컬러 토큰·폰트·컴포넌트)은 B2 백업 슬라이드로 두고 06에서 한 줄 언급. Figma에 「Design System · 밥송국 Retro Pixel」 섹션이 이미 있음
- 정보구조도·플로우차트는 Figma 「정보구조도·플로우」 페이지에서 캡처

### 07 시연: 시나리오와 백업
- 순서: 접속(꺼진 TV) → 전원 → 1번 채널(예능) 자동 재생 → 채널 ▲/숫자 키로 다른 채널 → 새로고침("먹기 싫어") → 9번 다음 1번 순환 (숫자 키 0은 이스터에그 컬러바, 시간이 남으면 보여줌)
- 백업: 녹화 영상(06:20 촬영)을 같은 슬라이드에 연결. 라이브 실패 시 즉시 전환
- 발표 전 점검(07:30~07:40): 노트북 소리 켜기, 와이파이, 배포 URL 접속

### 08 구현 방식·완성도: 심사 증빙 체크
- [ ] 배포 URL (웹) / Swagger URL / 저장소 URL / APK 다운로드 QR
- [ ] 인프라 구성도·ERD (WAS·DB 분리, HTTPS, CI/CD 여부 표기)
- [ ] 전역 예외처리와 응답 코드(200/201/400/404/500)
- [ ] 기능 → API 매핑 표 (B3 백업, 08에는 "전체 API 연동"만 한 줄)
- [ ] 스플래시 처리 여부 (가산점)
- ⚠️ 영상 수집 수치(하루 10개 크롤링 / DB 하루 100개 적재)는 채널 9개와 맞지 않아 서버와 확정 전까지 슬라이드에 쓰지 않는다

### 09 기대 효과 (11.22 분리: 기존 09를 기대 효과 / 검증 방법 2장으로 나눔)
- 카드 3장: 고르는 시간 단축(측정: 첫 영상 재생까지 걸린 시간) / 끊김 없는 시청(식사 20분 동안 채널만 돌리며 시청) / 놀이로의 전환("고르기"가 "채널 돌리기"로 바뀜)
- "고민 시간 0"은 검증 불가 → 측정 가능한 지표로 교체: 예) "영상 재생까지 걸린 시간(고르기 vs 채널 돌리기)"

### 10 검증 방법
- 카드 2장을 크게: ① 간이 설문(팀원·지인 N명, "고르다 식사가 끝난 경험 비율") ② 사용 테스트(고르기 vs 채널 돌리기, 재생까지 시간 비교)
- 사실/가설 구분 표기 유지. 결과 N명·수치는 06:00까지 입력 (슬라이드 내 [입력 필요] 문구는 07:00 최종 점검에서 전수 제거)

### 12 협업 과정: 발표용 3건 + Git
- 발표용 선별(★): ① 소리 자동재생 차단 → 전원 버튼(F7) ② 채널 번호 한 자리 확정 + 숫자 키 허용 ③ 서버 호스팅 로컬 vs 클라우드
- Git 협업 방식 한 줄(브랜치 전략·커밋 컨벤션·PR 규칙): 저장소 규칙 확인 후 기입 (Web 팀워크 10점이 커밋 분리·컨벤션을 봄)
- 디자인·서버·앱 관점의 조율 사례 각 1건은 해당 담당에게 물어 기록 필요 (지금 로그는 PM 관점 위주)

### 백업 슬라이드 (13 뒤, 발표에서는 넘김)
- B1 예상 질문: ① 제약이 컨셉인데 숫자 키는 왜 허용했나 ② 유튜브 임베드·저작권·쿼터는 어떻게 하나 ③ 로그인이 없는 이유 ④ 앱이 필요한 이유 ⑤ 채널을 왜 이 9개로 정했나(선정 기준 3가지)
- B2 디자인 시스템 (Figma 섹션 캡처)
- B3 기능 → API 매핑, 영상 수집 파이프라인 도식 (YouTube Data API → DB, 일 배치)
